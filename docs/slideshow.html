2. OP Patient Registration

Flow Diagram

Staff Login → Staff Dashboard → + Register Patient → Fill Form (General / Maternity / Other) ↓ Enter Vitals (Weight, BP, Temp, SpO2) → Payment (Cash/UPI) → Submit ↓ POST /api/v1/patients/ → OP ID Generated: OP-DDmmmYY → Token Generated

Key Steps & Outcomes

  • Unique OP-ID from day + phone + year ensures traceability
  • Vitals recorded at registration for baseline
  • Edit history: every update creates immutable patient_history snapshot

3. OP Prescription Flow

Flow Diagram

Doctor Login → Doctor Dashboard → Select Patient → + New Prescription ↓ Enter Diagnosis → Select Medicines (Inventory Dropdown) → Dosage + Frequency + Duration ↓ POST /api/v1/prescriptions/ → RX-NNNN Created → Reflects in Medical Desk

Key Steps & Outcomes

  • Medicine dropdown backed by live inventory (stock + price visible)
  • Prescription stored as JSON in medicines_json
  • Printable A4 layout with patient details + vitals + medicines
  • Prescription immediately available at Medical Desk for dispensing

4. Inpatient Admission

Flow Diagram

Doctor Dashboard → Inpatients Tab → + Admit Patient (select OP ID) ↓ Ward, Room, Bed, Doctor, Diagnosis → POST /api/v1/inpatients/ ↓ IP ID derived: OP-0374526 → IP-0374526 → Inpatient Management Page

Key Steps & Outcomes

  • IP ID mirrors OP ID suffix — ensures 1:1 traceability
  • Ward types: General, Maternity, ICU, Private, Semi-Private
  • Status lifecycle: Admitted → Transferred / Discharged
  • Full billing tracked via inpatient_billing_items

7. Medicine Returns

Flow Diagram

Sales Tab → Click Return → Enter Qty + Reason → POST /medicine-returns/ ↓ Atomic Transaction: 1. Create RET-NNNN record 2. Restore stock in inventory ← FIXED 3. Recalculate sale total_price = unit_price × (sold − returned) ← FIXED 4. Update payment_status → partial_return / full_return (OP & IP) 5. Adjust IP billing item (qty & total) 6. Write AuditLog (old/new JSON values)

Anti-Fraud Validation

  • Cannot return more than sold - already_returned
  • Return qty must be > 0
  • Rollback on any failure (atomic)

Test Coverage

test_medicine_returns.py — Stock restoration, price recalculation, over-return prevention, zero/negative qty, nonexistent sale

8. Due Tracking & Clearance

Flow Diagram

Dues Tab → List sales where status = "due" or "partial_return" ↓ Click Clear Due → POST /medicine-returns/dues/clear/{sale_id} ↓ payment_status → "cleared", cleared_at = now, due_amount = 0

Payment Status Lifecycle

StatusMeaning

dueIP sale — pending settlement
clearedDue settled at discharge

full_returnAll qty returned, total = 0

9. Finance & Audit Dashboard

Expense Management

  • Categories: Salary, Utilities, Rent, Supplies, Maintenance, Equipment, Insurance, Other
  • Admin-only CRUD
  • Date range filtering

Financial Summaries

  • Hospital: Patient income vs expenses
  • Medical Desk: Sales revenue + top medicines
  • Overall: Total income - expenses = net profit

Audit Trail

  • Patient History: Immutable edit snapshots
  • Audit Logs: RETURN transactions with old/new JSON
  • Sale Records: sold_by, payment_status, timestamps
  • Return Records: returned_by, reason, refund_amount
  • Billing Linkage: sale_ref_id traces billing ↔ sale
